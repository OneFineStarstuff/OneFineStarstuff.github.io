# **Monograph Editorial Policy: Macro System and Notational Integrity**\n\n### **1. Editorial Review Checklist for Notational Policy**\n\nThis checklist must be applied to all chapter submissions to ensure absolute compliance with the monograph's two-layer macro system. The goal is a source text that is semantically pure and a typeset output that is visually consistent.\n\n**Verification Steps:**\n\n1.  **Source Code Purity (The "No Raw Forms" Rule):**\n    - [ ] **Scan the `.tex` source file for any raw, presentational LaTeX.** The source code in the main body MUST NOT contain explicit subscripting or direct styling for policy-controlled symbols.\n    - **Example (INVALID):** `A map \(f: X \to Y\) is a morphism if \(x_1 \sim_I x_2 \implies f(x_1) \sim_J f(x_2)\).`\n    - **Example (VALID):** `A map \(f: X \to Y\) is a morphism if \(x_1 \simI x_2 \implies f(x_1) \simJ f(x_2)\).`\n\n2.  **Correct Semantic Macro Usage:**\n    - [ ] **Verify that the correct semantic macro is used for the intended mathematical object.** Ensure that macros are not used in a syntactically incorrect way.\n    - **Example (INVALID):** `The quotient map is \qI.` (Correct syntax, but should be used in math mode).\n    - **Example (INVALID):** `The quotient object is \(X/\simI\).` (Syntactically incorrect grouping).\n    - **Example (VALID):** `The quotient object is \(X/{\simI}\).`\n    - **Example (VALID):** `The quotient map \(\qI: X \to X/{\simI}\) is canonical.`\n\n3.  **Functor Notation Consistency:**\n    - [ ] **Confirm that the Semantic Quotient Functor is exclusively denoted by the macro `\QFunctor` (which renders as `Q`)** throughout the text, definitions, and diagrams.\n\n4.  **Absence of Contradictory Definitions:**\n    - [ ] **Ensure no local or chapter-specific `\newcommand` or `\def` statements exist** that override the centrally-defined policy macros from the monograph's main style file.\n\n### **2. Formal Specification of the Macro-Expansion Map**\n\nWe formally define the LaTeX macro system as a translation map `Φ` between two languages.\n\n-   Let `\mathcal{L}_{\mathrm{source}}` be the language of the LaTeX source files, where mathematical objects are represented by semantic macros (e.g., `\simI`, `\qJ`).\n-   Let `\mathcal{L}_{\mathrm{typeset}}` be the language of the final typeset PDF, where symbols are rendered in their full presentational form (e.g., `\sim_I`, `q_J`).\n\nThe macro-expansion engine of LaTeX implements the translation map:\n\n`Φ: \mathcal{L}_{\mathrm{source}} \to \mathcal{L}_{\mathrm{typeset}}`\n\nThis map `Φ` is governed by the following properties, which constitute our formal notation policy:\n\n1.  **Mathematical Interpretation Preservation:** `Φ` is strictly a presentational mapping. The mathematical interpretation of a statement in `\mathcal{L}_{\mathrm{source}}` must be identical to the interpretation of its image under `Φ`. For example, `Φ("\simI") = "\sim_I"` changes the syntax but not the meaning that it is the equivalence relation induced by the interpretation `I`.\n\n2.  **Representation Separation:** The domain `\mathcal{L}_{\mathrm{source}}` is the **semantic layer**, concerned only with *what* a symbol is. The codomain `\mathcal{L}_{\mathrm{typeset}}` is the **presentational layer**, concerned only with *how* a symbol appears. The map `Φ` is the unique bridge between these layers.\n\n3.  **Stability (Normal-Form Property):** An authoring workspace is in **normal form** if and only if all mathematical symbols covered by this policy are expressed using macros from `\mathcal{L}_{\mathrm{source}}`. `Φ` is stable because its definition is centralized; changes to the visual style of the monograph only require modifying the implementation of `Φ` (i.e., the `\newcommand` block), not the source text itself. This guarantees that `Φ(s)` is uniform for any statement `s` regardless of where it appears in the monograph.\n\n4.  **Contradiction-Free by Construction:** Since `Φ` is a function, any given macro `m ∈ \mathcal{L}_{\mathrm{source}}` has exactly one image `Φ(m) ∈ \mathcal{L}_{\mathrm{typeset}}`. It is therefore impossible for the same source macro to render in two different ways, ensuring a contradiction-free visual representation.\n
