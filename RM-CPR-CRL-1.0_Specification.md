# **Registry Manifest (RM) Standard**
## **Part 10: Conformance Reporting Language**
### **RM-CPR-CRL-1.0 — Version 1.0**

---

### **1. Scope**

This document specifies the **RM-CPR Conformance Reporting Language (CRL)**. It defines a normative, canonical object model for reporting the results of executing conformance tests (from RM-CPR-CTS-1.0) and adversarial test vectors (from RM-CPR-TVC-1.0) against an implementation.

### **2. Foundational Principles**

- **Reporting Fidelity:** The CRL object MUST be a complete and unaltered representation of the test execution output.
- **Report Completeness:** The CRL object MUST account for every assertion in the specified test suite, even if a test was not executed.

### **3. CRL as a Canonical Object**

**3.1 Normative**
The `CRL Report` is a canonical object type. Its formal structure SHALL be defined in the `RM-CPR-Schema-1.0` artifact. This ensures that a CRL Report is machine-readable and preserves the chain-of-custody from raw test output to a final certification decision.

### **4. CRL Object Model**

**4.1 Root Object: `CRL_Report`**

**4.1.1 Normative**
The root of a conformance report SHALL be the `CRL_Report` object. It MUST contain:
- `metadata`: Information about the context of the test run.
- `summary`: An aggregation of test results.
- `results`: An array of detailed assertion results.

**4.2 `metadata` Object**

**4.2.1 Normative**
The `metadata` object MUST contain:
- `reportId`: A unique identifier for this report (e.g., a UUID).
- `timestamp`: The ISO 8601 timestamp of the report generation.
- `implementationUnderTest`: Information identifying the software that was tested.
- `testSuite`: The identifier and version of the test suite used (e.g., `RM-CPR-CTS-1.0`).

**4.3 `summary` Object**

**4.3.1 Normative**
The `summary` object MUST contain counts for each possible test outcome: `pass`, `fail`, `error` (the test itself failed to run), and `skipped`.

**4.4 `results` Array**

**4.4.1 Normative**
The `results` array MUST contain one object for each assertion defined in the test suite. Each result object MUST include:
- `assertionId`: The ID of the test assertion (e.g., `GITO-C.ID-001`).
- `status`: The outcome of the test (`pass`, `fail`, `error`, `skipped`).
- `output`: A string containing any output generated by the test, such as error messages.
- `timestamp`: The timestamp of the test execution.

### **5. Conformance Reporting Profiles**

A CRL report can be used in different contexts. A claim of conformance SHALL specify the profile under which the report was generated.

- **`Minimal`**: Includes only the `summary` and failed `results`.
- **`Standard`**: Includes the `summary` and all `results`.
- **`Audit`**: Includes all fields from `Standard` plus additional metadata about the execution environment and security context.
- **`Certification`**: The profile required for a formal conformance claim, equivalent to the `Audit` profile.
